'영수증 OCR 전체 거래 입력' 풀빌드는 NO-GO, 단 '카드연동 마트/코스트코/편의점 거래의 품목 분해(enrichment)'로 극단적으로 좁히고 2개 게이트(촬영 빈도 실측 + 한국 실물 영수증 line-item F1 >85% 실측)를 통과할 때만 조건부 GO.

### averaged
기준별 평균(채점1 skeptic / 채점2 builder → 평균):
- 수요(demand): 3 / 3 → 3.0
- 경쟁평가(competitor_sentiment): 4 / 4 → 4.0
- 차별성(differentiation): 3 / 5 → 4.0
- 구현용이(feasibility): 7 / 5 → 6.0
- 가성비(cost_efficiency): 5 / 4 → 4.5
- 리텐션(retention): 2 / 2 → 2.0
총평균: 3.0+4.0+4.0+6.0+4.5+2.0 = 23.5 / 60
(원점수 합계: 채점1 24/60, 채점2 23/60 → 산술평균 23.5/60)

### key_risks
1) 리텐션(평균 2.0, 최저점)이 구조적 핸디캡: 수동 영수증 촬영은 2주차 급이탈·3개월 내 방치, '24시간 안에 안 찍은 영수증은 평생 안 찍힘'. 트리거0 카드 자동연동과 정면 경쟁.
2) 수요(3.0)가 약함: 한국은 카드+모바일 75.5% / 현금 15.9%(11년간 41.3%→15.9% 붕괴)로 영수증 발생 자체가 우하향. 자발적 촬영 동기는 가계부가 아니라 리워드 적립·세무 증빙인데 후자는 홈택스+카드연동(무료, 국가제공)이 이미 흡수.
3) 결정적 비대칭: 유일하게 비어있는 진짜 차별점(line-item 품목분해)에 = 가장 높은 오류율(field 95%+ vs line-item 89%↓, 한국 실물 감열지 KORIE 벤치마크 zero-shot 전체정확도 23%/F1 25%) + 가장 큰 캡처 마찰 + 가장 약한 리텐션 + 추가 보정 UX 공수가 동시에 겹침.
4) '미개척 차별기능' 전제 오류: 영수증 OCR 가계부는 머니야·똑똑한가계부·영수증스캐너·빌리 등 이미 점유한 레드오션 니치이며, 이들이 시장 1위(뱅크샐러드·토스)를 못 잡았다는 것 자체가 'OCR이 가계부 핵심 차별점이 못 됨'의 시장 검증 결과.
5) 단위경제 열위: 한계비용은 무시 가능하나(GPT-4o vision 3~7원) 카드연동(한계비용 0) 대비 구조적 불리. 진짜 비용은 API요금이 아니라 '쓰지 않을 기능의 개발 기회비용 + 한국어 line-item 정확도 확보·교정 UX 공수'.

### recommended_scope
[GO 전환 조건 — 2개 게이트 모두 통과해야만 GO]
(게이트1 수요) dogfooding으로 '주당 실제 영수증 촬영 발생률'과 '교정 부담'을 먼저 측정. 2주차 이탈 패턴 재현 시 보류.
(게이트2 정확도) 한국 실물 영수증(감열지·바램·접힘 포함) 50~100장으로 GPT-4o vision vs CLOVA Receipt vs Upstage의 line-item F1을 실측. >85% 미달 시 보류(KORIE상 zero-shot은 23%까지 폭락).

[권장 범위] 풀빌드 금지. 셀링포인트를 'OCR/증빙/현금기록'이 아니라 '이미 카드연동으로 들어온 이마트 87,000원 한 줄을 식료품/생필품/군것질로 자동 분해(enrichment)'로 한정 → 현금 감소 추세와 무관하게 카드거래에도 가치 유지. 증빙/세무는 홈택스+카드연동에 패배하므로 핵심 가치제안에서 제외(부가 메모 수준).

[OCR 엔진] dogfooding/저트래픽 단계는 고정비0·기존 OpenAI 키 재사용 가능한 GPT-4o(또는 mini) vision이 1순위 PoC. CLOVA Receipt는 한국어 line-item을 items 구조 JSON으로 바로 주는 강점이 있으나 월 1.8만~58만 고정비(0호출에도 부과)라 트래픽 증가 후 단계 전환. Upstage($0.04/장, 낮은 고정비)는 PoC 비교군 포함. Veryfi/Mindee는 한국어 미검증+고비용으로 배제.

[타깃] 매스 아님. '품목 단위로 소비를 분석하려는 꼼꼼한 헤비유저' 소수 세그먼트(가족 공동지출 분담, 마트 장보기 품목분석 등 특정 유스케이스). 자영업/프리랜서 세무는 셀링포인트로 잡지 말 것.

[비용통제] 품목→카테고리 매핑은 기존 OpenAI 분류 파이프라인 재사용(영수증당 LLM 1회 추가). 엔지니어링은 추출 정확도보다 '오류 수정 1탭 UX'와 안정성에 집중(평점·리텐션은 정확도보다 보정 UX가 좌우). 품목 분해는 rate-limit 또는 유료티어로 단위경제 보호.

[게이트 미통과 시] v2 우선순위를 낮추고 '카드 자동연동 강화 + 현금 보조 입력(자연어)'에 자원 재배치하는 것이 ROI상 합리적.

### rationale
두 채점단(skeptic 24/60, builder 23/60)이 독립적으로 거의 동일한 결론(CONDITIONAL)과 패턴에 수렴했고, 기준별 점수도 수요·경쟁평가·리텐션에서 완전 일치한다. 총평균 23.5/60(39%)는 중간 이하로, 풀빌드 GO를 정당화하기엔 명백히 부족하나 완전 NO-GO로 사망선고하기엔 과하다. 그 이유는: (a)기술 한계비용이 거의 0이고 기존 OpenAI 자연어 분류기를 재사용할 수 있어 '좁은 가설검증' 자체는 저비용이며(구현용이 평균 6.0으로 유일하게 높음), (b)카드연동이 구조적으로 줄 수 없는 비대체 가치 한 줄기(line-item 품목 분해)가 실제로 존재하기 때문이다(군것질 월20만원 발견 사례, 후잉 split 기능 수요 실재). 다만 이 유일한 진짜 차별점에 최고 오류율·최대 캡처 마찰·최저 리텐션·추가 UX 공수가 동시에 겹치는 비대칭이 가성비를 결정적으로 깎는다. 따라서 무차별 풀빌드가 아니라, 범위를 'enrichment'로 극단적으로 좁히고 정확도·수요 2개 게이트를 사전 통과시키는 조건부 GO가 정직한 판정이다. 점수가 애매(39%)하므로 규칙대로 CONDITIONAL로 두고 GO 전환 조건을 명시했다.
