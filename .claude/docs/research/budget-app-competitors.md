## 3. 구조적 인사이트

- **자동연동 vs OCR**: 자동연동(뱅크샐러드·토스·Copilot)은 디지털 결제에 강하나 **item-level 맥락이 없음**. OCR은 현금·환급·세금·**영수증 품목 분리(splitting)** 에 강함.
- 한국 개인 사용자에게 영수증 촬영은 일반 가계부 맥락에선 **마찰만 증가** → 약한 wedge.
- 진짜 가치는 자동연동이 못 푸는 빈틈: **현금/품목분리/세금증빙**.

## 4. 시장 공백 (MVP 공략 지점)

1. **라인 아이템 분리(Line-Item Split)** — 한국 소비자용 앱 중 마트 영수증을 "식비/생필품/주류"로 자동 분해하는 곳 **없음**. 멀티모달 Vision의 킬러 기능.
2. **N잡러·프리랜서 세금 OCR** — 5월 종합소득세 대비 "업무비용 vs 개인지출" 원탭 분리 + 세무사 제출용 export. Foreceipt 한국판 / 삼쩜삼의 소비자 친화 버전.

## 5. 추천 wedge (Codex 결론)

> **프리랜서·1인사업자용 영수증 기반 세금/경비 정리 앱**
> 영수증 한 장 → 금액·날짜·상호·**부가세·사업자번호·경비 카테고리** 자동 → **월별 세무사 제출용 CSV/PDF**

- 방어 니치 우선순위: ① 프리랜서·1인사업자(결제의향↑, 최우선) ② 소규모 팀(B2B 확장) ③ 영수증 분할(바이럴↑ 리텐션↓) ④ 현금 사용자(시장 축소)
- 차별화: 부가세·품목·사업자번호 추출 / 세무 카테고리 / 개인vs사업 신뢰도 점수 + **검토 큐** / 한국 경비규정.

## 6. 기술 권고

- **한국어 영수증 OCR**: Naver CLOVA OCR 또는 Upstage Solar OCR 필수(Tesseract/Google Vision 대비 우위). 빠른 MVP는 Mindee/Taggun(JSON 반환).
- **파이프라인**: 저가 OCR 선처리 → LLM은 분류·구조화만 → 멀티모달 LLM 호출 비용 절감.
- **MyData 라이선스**는 인디 진입장벽 매우 높음 → 은행 CSV 가져오기 + 영수증 OCR "보강" 플로우로 시작.

## 7. 주요 리스크

| 리스크 | 대응 |
|---|---|
| 촬영 깜빡(습관) | 입력 마찰 최소화가 생명 |

| 개인정보(위치·의료·약국) | 민감정보 처리 주의 |

## 8. MVP 스코프 (권장)

촬영 → 추출 → 분류 → 보정(검토 큐) → 저장 → 월별 export. **6단계만.**
예산·순자산·투자 대시보드 등 "가계부 클론" 기능은 v2로 미룬다.
