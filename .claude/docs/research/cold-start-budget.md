# 콜드스타트 예산 추천 (온보딩 초안 가이드) — 리서치

> Source: Codex (gpt-5.5) — Gemini 두 모델 쿼터 소진으로 폴백. 2026-06.
> 배경: `suggest_budgets`는 직전 3개월 평균 기반이라 신규 사용자(데이터 0~2개월)는 빈 값. 첫 1~2달 초안 가이드가 필요.

## 핵심 결론
- **콜드스타트 1순위 = 소득 입력 + 통계 기반 % 배분.** 월 실수령액을 묻고 통계청 가계동향 비율로 카테고리 초안 즉시 생성. 소득 거부 시 고정 템플릿 fallback.
- **부분 월 외삽은 비추**(월 5일차 택시 1건 ×6 → 과대추정). 30일+ 누적 후 보조 수단으로만.
- **소비예산 = 실수령 × 70%** (통계청 2025 소비성향 ~68%). 나머지 30%는 저축·투자·부채.

## 카테고리별 추천 비율 (소비예산 기준, 합 100%)
| 카테고리 | 비율 |
|---|---|
| 식비 | 24% |
| 카페/간식 | 6% |
| 생활/마트 | 5% |
| 교통 | 12% |
| 주거 | 18% |
| 통신 | 4% |
| 문화/여가 | 8% |
| 건강/의료 | 8% |
| 쇼핑 | 10% |
| **카드대금** | **0%** (결제일일 뿐 — 원거래에서 이미 계산, 이중계산 방지) |
| 기타지출 | 5% |

예: 실수령 300만 → 소비예산 210만 → 식비 504,000 / 주거 378,000 …

## UX 권장
- 온보딩 3문항으로 보정: ①세후 월수입, ②주거비(월세/관리비) 예산 포함 여부, ③교통수단. (MVP는 ①만으로 충분)
- "임시 예산입니다, 언제든 수정 가능해요" 문구로 부담 감소.
- 주거비 편차가 가장 큰 변수(월세 포함 시 30%+ 초과 가능) → 1문항 보정 또는 힌트.

## 단계적 개인화 로드맵
- 0–30일: 통계 템플릿
- 30–90일: 실거래 70% + 템플릿 30% 블렌딩
- 90일+: 3개월 평균 (현재 로직)

## 앱 벤치마크
- YNAB=제로베이스 직접 배정 / Monarch=연결계좌 과거소득 자동계산 / PocketGuard="In My Pocket" 잔여중심 / Copilot=과거데이터 import 후 추천.
- 한국 앱(뱅크샐러드·토스)=카드연동 자동분류 위주. 무이력 통계기반 초안 생성은 공개문서상 드묾 → 차별 여지.

## 캐시매니저 적용 권장
1. `GET /budgets/template?income_minor=` 신규 — 소득 받아 % 배분 초안 반환(카드대금 제외).
2. 기존 `GET /budgets/suggestions`(3개월 평균)는 유지. 둘을 BudgetScreen에서 선택 제공.
3. v1은 소득 1입력만. 블렌딩·3문항은 v2.

## 갱신 (dogfooding 반영, 2026-06)
1개월 시뮬에서 발견: 월세 거주자(주거 62만)가 주거 18%(37.8만) 한도를 즉시 초과 — 주거비는 평균이 무의미(월세 vs 전세/자가). **고정비 vs 변동비 분리** 원칙 적용.
- **고정비(주거·통신·카드대금)는 템플릿에서 제외** — 사람마다 편차 크고 사용자가 정확히 아는 숫자라 추측보다 직접 입력이 낫다. ("월세 물어보기"보다 질문0·정확·솔직)
- **변동비만** 기존 통계 비율로 채움(식비24·교통12·쇼핑10·문화8·의료8·카페6·마트5·기타5%, 합 78%). 변동 비율을 100%로 재분배하면 과다(저축 7%)이라 원래 비율 유지(저축 ~23% 확보).
- 문구: "조절 가능한 지출만 먼저 채워드려요. 주거비·통신비·카드대금은 실제 금액을 직접 넣어주세요."
- v2: 가처분소득 앵커링(변동풀 = 소득 − 고정비 − 저축).
