# 신용카드 처리 (카드대금 이중계산 문제) — 리서치

> Source: Codex (gpt-5.5), 출처 링크 포함. 2026-06.
> 문제: 카드는 한 달간 여러 개별결제를 묶고, 다음달 카드대금 1건이 통장에서 빠짐.
> 개별결제 + 카드대금을 둘 다 지출로 기록하면 **이중계산**(예: 5만원이 10만원으로).

## 표준 접근 3가지
- **(A) 결제 시점 기록(expense-at-purchase, 권장)**: 카드 긁는 순간을 실제 지출로 기록(카테고리·날짜·상호). 월 카드대금은 **이체(transfer)** — 지출 아님, 합계에서 제외.
- **(B) 카드대금일 기록(cash/payment-date)**: 개별결제는 무시하고 다음달 통장 출금(카드대금)만 지출로. 단순하지만 카테고리 분석 불가 + 한 달 시차.
- **(C) 부채계정 모델**: 카드를 부채계정으로. 결제=지출+부채증가, 대금=자산감소+부채감소. 연동 가계부용.

## 실제 앱 처리
- **YNAB**: 카드=계정, 카드대금은 반드시 **transfer**로 입력. (support.ynab.com)
- **Monarch**: 원결제=지출, 카드대금=Credit Card Payment(이체) — 예산·현금흐름·지출 합계에서 제외. "안 그러면 $50이 $100 된다"고 명시.
- **Copilot**: 타입 Regular/Income/Internal Transfer. 월 카드 상환=Internal Transfer(개별거래가 이미 집계됨).
- **뱅크샐러드**: `이체`는 자산이동이라 수입/지출 합계에 영향 없음. 카드 결제예정대금은 자산에, 승인내역은 가계부에 분리.
- **편한가계부**: 수입/지출/**이체** 지원, 이체는 합산 제외. 카드 자산모델(결제계좌·정산일·결제일·자동결제)로 카드대금=은행출금→카드결제(소비 아님).
- **토스**: 카드대금·자기계좌 이체를 자동 제외, 수동 제외도 가능(3rd-party 분석).

## 권장 — 우리 앱(단일 ledger, NL 입력, expense-at-purchase)
**(A) + `transfer` 방향 추가.** 월 카드대금을 transfer로 기록해 지출 합계·예산·인사이트·카테고리 지출에서 제외.
- `어제 쿠팡 3만원 카드` → expense, 쇼핑.
- `오늘 카드대금 120만원 빠짐` → transfer(car드대금), 지출 제외.
- 지출 요약="무엇을 소비했나", 이체 뷰="현금이 어디로 이동했나".

### 데이터모델 변경(최소)
```
transactions.direction: expense | income | transfer   (현재 expense|income)
transactions.transfer_type: optional (credit_card_payment 등)  ← 선택
```
- 모든 지출/예산/인사이트 쿼리는 명시적으로 `direction='expense'` 필터(대부분 이미 그러함).
- 현재 `카드대금` 0% 예산만으로는 부족 — 요약·최다지출·AI답변·전월대비에서 여전히 모호.

### 함정
- **시차**: 5월 결제가 5월 지출, 현금은 6월에 나감(소비 분석엔 정상, 현금흐름 뷰는 별도).
- **카드대금만 기록하는 사용자**: 개별결제 안 적으면 지출 0으로 보임 → NL이 `카드대금/카드값/신용카드 결제` 감지 시 "개별내역 이미 기록했으면 이체, 카드값만 적는 방식이면 지출" 분기/안내.
- **이자·연회비·수수료**: 진짜 지출(이체 아님). 가능하면 분리.

## 적용 계획(권장)
1. 마이그레이션: direction에 'transfer' 허용(check 제약 갱신).
2. 스키마 Literal + NL: 카드대금류 → transfer 기본, 사용자 override 허용.
3. 지출 집계 전부 `direction='expense'` 보장. 내역에 transfer는 별도 스타일/뱃지.
