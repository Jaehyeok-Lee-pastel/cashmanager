# 캐시매니저 — 케이스 스터디 (만든 과정 · 결정 · 배운 점)

> 이 문서는 "무엇을 만들었나"보다 **"어떻게 결정하고 검증했나"** 를 담는다. 포트폴리오용 요약.

## TL;DR
혼자서 **AI 네이티브 풀스택 가계부**를 설계·구현·QA했고, 그 과정에서 *기능을 "멋있어서"가 아니라 수치 검증으로* 넣고 뺐다. 결과적으로 "잘 만든 것 ≠ 팔리는 것"을 데이터로 구분했다.

## 1. 제품
"입력이 안 귀찮은" 개인 가계부. 자연어 한 줄("맥날 만이천원") → LLM 파싱 → 1탭 confirm → 저장.
스택: React 19 / FastAPI / Supabase(Postgres·RLS) / OpenAI.

## 2. 엔지니어링 하이라이트
- **NL 파이프라인**: 정규식 선처리(한글 수사 "만이천원"=12,000·상대날짜) → 학습맵 → LLM 1회(Structured Outputs) → 미저장 미리보기 → confirm. 비용·오류·환각을 단계로 분리.
- **학습 루프**: 상호→카테고리 매핑을 저장해 "쓸수록 LLM 없이 정확·저렴".
- **보안**: 전 테이블 RLS + service_role 우회 전제하 서비스 레이어 소유권 재검증 + DB 트리거 방어.
- **품질**: 분류 정확도 **eval 하니스 176케이스 100%**(회귀 감시 스크립트), 백엔드 **pytest 57**, 빌드/타입체크 통과.

## 3. 검증 기반 의사결정 (이 프로젝트의 핵심 차별점)
기능을 직감이 아니라 **다중에이전트 수치 채점**으로 결정했다.

| 결정 | 방법 | 결과 |
|---|---|---|
| 영수증 OCR을 만들까? | 수요·경쟁·구현·가성비 6기준 채점 | **CONDITIONAL 23.5/60 → 보류** (리텐션·수요 약함, 이미 레드오션) |
| 다음 기능은? | 8개 후보 5기준(ROI·AI차별화·리텐션…) 채점 | **F1 월예산 40/50 만장일치 1위** → F2/F3 |
| 폴리시 vs 전진? | 4안 판정단 채점 | **D 하이브리드 42/50** (작은 보정 후 전진) |

→ "차별기능처럼 보였던 OCR"을 **검증으로 보류**하고, ROI 1위 기능으로 전진한 게 가장 시니어다운 판단이었다.

## 4. 냉정한 시장 판단
- 일반 소비자 가계부의 약점은 **품질이 아니라 시장 구조**(MyData 불가·무료 슈퍼앱·수동입력 리텐션·낮은 지불의향).
- 결론: **상업성 낮음(~3/10)**, 그러나 **개인용·포트폴리오 가치 높음**. "보완"이 아니라 "지불 고통이 큰 다른 문제"로 가야 돈이 됨 — 이라는 판단까지 데이터로 내렸다.

## 5. 도구·프로세스
Claude Code 오케스트레이션 + Codex(설계리뷰)·Gemini(리서치) 위임 + **Workflow 다중에이전트**(설계 토너먼트·다차원 적대적 리뷰·수치 audit). 단일 작성자 원칙으로 통합.

## 6. 배운 점 (한 줄씩)
- 만들 줄 안다 + **검증할 줄 안다** + **시장을 읽을 줄 안다** — 이 셋이 분리된 역량이고, 셋째가 가장 희소하다.
- fast-path 같은 "비용 최적화"가 **핵심 가치(자동분류)를 죽이는** 함정이 될 수 있다(QA로 발견·수정).
- 신형 LLM API의 작은 변화(`max_tokens`→`max_completion_tokens`)가 *모든 분류를 조용히 죽이고* 있었다 — **에러를 삼키지 말 것**.
